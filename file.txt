1. Explain the differences between `var`, `let`, and `const` in JavaScript regarding variable scope, hoisting, and reassignment.

`var`, `let`, and `const` are all ways of creating variables in JavaScript, but they work differently.

 A.scope-  `var` is function-scoped, while `let` and `const` are block-scoped. 
This means that `let` and `const` only work inside the `{ }` where they were created, while `var` can be accessed throughout the function.

 B.Hoisting- `var`, `let`, and `const` are all hoisted, but they behave differently. With `var`, the variable is initialized as `undefined`, so we can technically access it before its declaration. With `let` and `const`, we cannot use the variable before declaring it because JavaScript will give us an error.

C.Reassignment- a variable declared using `var` or `let` can be given a new value later. However, a variable declared using `const` cannot be reassigned after it has been given a value.

For example:

`let age = 19;`
`age = 20;`

This works because `let` allows reassignment. But:

`const age = 19;`
`age = 20;`

will give an error because `const` cannot be reassigned.

So, in simple terms, `var` is the older way of declaring variables, `let` is used when the value might change, and `const` is used when the value should not be reassigned.

//QUESTION 2

 What are the primitive data types available in JavaScript, and how do they fundamentally differ from reference types like arrays and objects?

JavaScript has seven primitive data types. They are String, Number, BigInt, Boolean, Undefined, Null, and Symbol. These are used to represent simple values. 
For example, a String can store text like `"Hello"`, a Number can store values like `19`, and a Boolean can be either `true` or `false`.

Primitive values are different from reference types such as arrays and objects. When we create a primitive variable, the variable holds the actual value.
 If we copy the variable and change the new variable, the original one is not affected.

Arrays and objects work differently because 
variables hold a reference to the data rather than directly holding the
 whole object or array. 
 This means that if two variables refer to the same object or array, changing the object or array through one variable can also affect what we see through the other variable.

For example, if two variables refer to the same object and we change a property using one variable, 
the change can also be seen using the other variable. 
This is the main difference between primitive values and reference types.

3. Discuss the difference between loose equality (`==`) and strict equality (`===`). 
Why is strict equality generally considered a best practice?

The difference between `==` and `===` is that `==` checks whether two values are equal, while `===` checks whether the values are equal and also have the same data type.

For example, `5 == "5"` is true because JavaScript converts the string `"5"` into a number before making the comparison. However, `5 === "5"` is false because one is a number and the other is a string.

Strict equality (`===`) is generally considered a best practice because it does not automatically convert the data types.
 This makes the code easier to understand and helps avoid unexpected results when comparing values.

Therefore, we normally use `===` when we want to make sure that both the value and the data type are the same.

///QUESTION 4

4. How do logical operators (`&&`, `||`, `!`) evaluate expressions, and what is meant by "short-circuit evaluation"?

Logical operators are used to combine or change conditions in JavaScript.

The `&&` operator means AND. It returns true when both conditions are true. The `||` operator means OR, and it returns true when at least one of the conditions is true. The `!` operator means NOT and is used to reverse a Boolean value. For example, if a value is `true`, using `!` will make it `false`.

Short-circuit evaluation means that JavaScript can stop checking an expression once it already knows the result. For example, with `&&`, if the first condition is false, JavaScript does not need to check the second condition because the whole expression cannot be true. With `||`, if the first condition is true, JavaScript can stop because the whole expression is already true.

This helps JavaScript avoid doing unnecessary checks when evaluating logical expressions.

A `switch` statement can be used when we want to compare one value with several possible values.

 It is similar to the final `else` in an `if...else if` statement. It gives us a way to handle a

2. Short-Circuit Logic:

The && (AND) and || (OR) operators use short-circuit evaluation. This means JavaScript stops evaluating an expression as soon as the result is known.

With &&, if the first value is false, JavaScript does not need to evaluate the second value.

With ||, if the first value is true, JavaScript does not need to evaluate the second value.

The || operator can be used to provide a default value. For example:

let username = "";
let name = username || "Guest";

console.log(name);

The output will be:

Guest

3. The Strict Equality Operator:

The === operator is generally recommended instead of == because it compares both the value and the data type without automatically converting one type into another.

For example:

5 == "5"

This is true because the == operator performs type coercion and converts "5" into a number.

However:

5 === "5"

This is false because 5 is a number while "5" is a string.

Using === helps prevent unexpected results caused by type coercion.

5. Nested Logic Transformation:

A nested if...else structure can be rewritten using a switch statement when checking one variable against several specific values.

Example:

let day = "Monday";

switch (day) {
case "Monday":
console.log("Start of the week");
break;
case "Friday":
console.log("Almost the weekend");
break;
default:
console.log("Regular day");
}

A switch statement is useful when comparing one value against several specific values.

A ternary operator is better for a simple condition with two possible results.

Example:

let age = 20;
let status = age >= 18 ? "Adult" : "Minor";

In general, if...else is useful for complex conditions and ranges, switch is useful for multiple specific values, and the ternary operator is useful for short and simple conditions.

6. The Loop Lifecycle:

A for loop has three expressions in its header:

for (initialization; condition; final-expression)

 Initialization: sets the starting value of the loop variable.
 Condition: checks whether the loop should continue running.
 Final-expression: usually updates the loop variable after each iteration.

The final-expression executes after the loop body has finished running and before the next condition is checked.

For example:

for (let i = 0; i < 3; i++) {
console.log(i);
}

The i++ runs after each execution of the loop body.

7. Termination Hazards:

A loop invariant is a condition or value that remains consistent during the execution of a loop and helps maintain the correctness of the loop.

To make sure a while loop eventually reaches its termination condition, the programmer should update the variable used in the condition inside the loop.

For example:

let count = 0;

while (count < 5) {
console.log(count);
count++;
}

Here, count++ changes the value of count on every iteration. Eventually, count becomes 5, making the condition false and stopping the loop.

8. Break vs. Continue:

The break keyword immediately stops the entire loop. When break is used, the loop ends and the program continues with the code after the loop.

The continue keyword does not stop the loop. Instead, it skips the rest of the current iteration and moves to the next iteration.

For example:

for (let i = 0; i < 5; i++) {
if (i === 2) {
continue;
}


if (i === 4) {
    break;
}

console.log(i);


}

The continue skips 2, while the break stops the loop when i reaches 4.

The counter or iterator is normally updated according to the loop structure. continue does not reset or stop the counter, while break stops the loop completely.

//QUESTION 12

 While vs. Do-While:

A while loop checks the condition before running the code. If the condition is false from the beginning, the loop will not run at all.

A do...while loop runs the code at least once before checking the condition.

Example:

let number = 10;

while (number < 5) {
console.log("While loop");
}

do {
console.log("Do-while loop");
} while (number < 5);

The while loop does not print anything because 10 < 5 is false.

The do...while loop prints "Do-while loop" once because the code runs before the condition is checked.

 Declaration vs. Expression:

A Function Declaration is a function created using the function keyword and a function name.

Example:

function greet() {
console.log("Hello");
}

A Function Expression stores a function inside a variable.

Example:

const greet = function() {
console.log("Hello");
};

Function Declarations are hoisted, which means they can be called before they appear in the code.

Example:

greet();

function greet() {
console.log("Hello");
}

Function Expressions are not available before the variable is initialized, so they should be called after they are defined.

 Parameters and Rest/Spread:

The arguments object is an array-like object that contains all the arguments passed to a traditional function. It does not work in arrow functions.

Example:

function add() {
console.log(arguments);
}

The Rest Parameter uses ...args to collect multiple arguments into a real array.

Example:

function add(...args) {

}

The Rest Parameter is preferred in modern JavaScript because it works with arrow functions and provides a real array that can be used with array methods such as map() and reduce().

 QUESTION 15. 
Arrow Function Anatomy

The original function is:

function multiply(a, b) {
return a * b;
}

It can be converted into an arrow function as:

const multiply = (a, b) => a * b;

In a concise arrow function, the function keyword is removed and replaced with =>.

The curly braces and return keyword can also be omitted when the function has a single expression. The expression is automatically returned.

16. Higher-Order Concepts:

If a function A is passed as an argument to another function B, function A is commonly called a callback function.

Function B receives function A as an argument and can execute it when needed.

Example:

function greet(name) {
console.log("Hello " + name);
}

function processUser(callback) {
callback("June");
}

processUser(greet);

In this example, greet is the callback function. The data "June" is passed to the callback when function B calls it.

 //QUESTION 17
 Global vs. Local:

The Global Object is an object that is available throughout the JavaScript environment. In browsers, it is commonly represented by window. In Node.js, the global object is called global.

Variables placed in the global scope can be accessed from many parts of a program.

Polluting the global scope means creating too many global variables. This can cause naming conflicts, make code harder to maintain, and make it difficult to track where variables are being changed.

It is generally better to keep variables inside functions or blocks when they are only needed there.

18. Block Scope vs. Function Scope:

The var keyword is function-scoped. This means a variable declared with var inside a function can be accessed throughout that function.

The let and const keywords are block-scoped. This means they are only available inside the block where they are declared, such as an if statement or a for loop.

Example:

if (true) {
let name = "June";
const age = 20;
var enrolled = true;
}

The variables name and age cannot be accessed outside the if block, but enrolled can be accessed outside the block if it is inside the same function.

ES6 introduced let and const, which made it easier to control the scope of variables inside blocks, if statements, and for loops.

//QUESTION 19
Shadowing:

Variable shadowing happens when a local variable has the same name as a variable in an outer or global scope.

Example:

let name = "June";

function greet() {
let name = "Alice";
console.log(name);
}

greet();

The output is:

Alice

The JavaScript engine uses the variable from the nearest scope. Therefore, the local name is used instead of the global name.

22. Temporal Dead Zone:

The Temporal Dead Zone (TDZ) is the period between entering a scope and the point where a let or const variable is declared.

Trying to access a let variable before its declaration causes a ReferenceError.

Example:

console.log(name);
let name = "June";

This produces a ReferenceError.

With var, the variable declaration is hoisted and initialized with undefined.

Example:

console.log(name);
var name = "June";

The output is:

undefined

Therefore, let and const cannot be accessed before their declarations, while var can be accessed but has the value undefined until its assignment.
